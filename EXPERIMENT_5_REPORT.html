3. Theory Questions

1. What is MongoDB Atlas, and why is it used? MongoDB Atlas is MongoDB's fully managed cloud database service. It hosts clusters on AWS/GCP/Azure and handles provisioning, backups, scaling, monitoring and security (IP allow-list, users, TLS), so developers do not install or maintain database servers. It has a free tier, which suits development and academic projects.

2. What is Mongoose? Explain the purpose of schemas and models. Mongoose is an ODM (Object Data Modeling) library for MongoDB and Node.js. A schema defines the structure of documents in a collection: field types, defaults, and validation rules (required, min, enum). A model is a class compiled from a schema (mongoose.model('MenuItem', menuItemSchema)) that provides the methods to query and modify the collection (find, create, …).

3. What is the purpose of MONGODB_URI and mongoose.connect()? MONGODB_URI is the connection string (host, credentials, database name, options) stored as an environment variable. mongoose.connect(uri) opens the connection pool to that database; all models use this connection for their operations.

4. Differentiate between in-memory storage and MongoDB storage.

In-memory (arrays) MongoDB
Data lives in RAM; lost on every server restart Persisted on disk; survives restarts
Single process only Shared by many servers/clients
No validation, manual ID generation Schema validation, auto ObjectId
Linear scans with filter/find Indexed, query-optimised
Not scalable Scalable (replication, sharding)

5. Purpose of the Mongoose methods

  • find(filter) – returns all documents matching the filter (all if empty).
  • findById(id) – returns one document by its _id, or null.
  • create(data) – validates and inserts a new document.
  • findByIdAndUpdate(id, update, {returnDocument:'after', runValidators:true}) – updates a document and returns the updated version.
  • findByIdAndDelete(id) – removes a document and returns the deleted one.

6. What is MongoDB ObjectId? A 12-byte (24 hex characters) unique identifier automatically assigned as _id to each document. It contains a timestamp, random value and counter, so it is unique across machines without a central counter and roughly sortable by creation time.

7. Why should database credentials be stored in a .env file? Credentials hard-coded in source end up in Git history and public repositories, where they can be stolen and abused. .env keeps secrets outside the code, is listed in .gitignore, and lets each environment (dev/test/prod) use different values without code changes. Only .env.example (placeholders) is committed.

const mongoose = require('mongoose');

const connectDB = async () => {
  const uri = process.env.MONGODB_URI;
  if (!uri) {
    console.error('❌ MONGODB_URI is not defined. Copy .env.example to .env and set it.');
    process.exit(1);
  }
  try {
    const conn = await mongoose.connect(uri);
    console.log(`✅ MongoDB Connected: ${conn.connection.host} (db: ${conn.connection.name})`);
  } catch (error) {
    console.error('❌ MongoDB connection failed:', error.message);
    process.exit(1);
  }
};
module.exports = connectDB;

4.5 Validation and error handling

const isValidId = (id) => mongoose.Types.ObjectId.isValid(id);   // 400 for malformed ObjectId

const handleError = (res, error, fallback) => {
  if (error.name === 'ValidationError')                           // schema rule violated → 400
    return res.status(400).json({ success: false,
      message: `Validation Error: ${Object.values(error.errors).map(e => e.message).join(' ')}` });
  if (error.name === 'CastError')                                 // wrong type → 400
    return res.status(400).json({ success: false, message: `Invalid value for "${error.path}"` });
  res.status(500).json({ success: false, message: fallback, error: error.message });
};
