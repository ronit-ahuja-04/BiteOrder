3. Theory Questions

1. What are WebSockets? Explain their purpose.

WebSocket is a communication protocol (RFC 6455) that provides a persistent, full-duplex connection between a client and a server over a single TCP connection. The connection starts as an HTTP request that is "upgraded" to WebSocket, after which both sides can send messages to each other at any time.

Purpose: real-time, low-latency, two-way communication – chat, live notifications, live dashboards, multiplayer games – without the client having to keep polling the server.

2. What is Socket.IO? How is it different from WebSockets?

Socket.IO is a JavaScript library (server: socket.io, client: socket.io-client) for real-time, event-based, bidirectional communication. It uses WebSocket when available and falls back to HTTP long-polling when it is not.

• WebSocket is only a low-level protocol: raw messages, no built-in reconnection, rooms or events.
• Socket.IO is a library built on top of it: named events (emit/on), automatic reconnection, heartbeat (ping/pong), rooms and namespaces, broadcasting, acknowledgements and transport fallback. A Socket.IO client can only talk to a Socket.IO server, not to a plain WebSocket server.

4. What is the purpose of socket.io and socket.io-client?

socket.io is installed in the Node.js backend. It attaches to the HTTP server, accepts client connections, and lets the server listen for and emit events (for example io.emit("notification", data)).

socket.io-client is installed in the React frontend. It opens the connection to the server (io(url)), listens for events with socket.on() and can send events with socket.emit().

5. Explain the purpose of io.on("connection") in Socket.IO.

io.on("connection", callback) registers a handler that runs every time a new client connects. The callback receives that client's socket object, which has a unique socket.id and is used to listen for that client's events (socket.on) and to send events to it (socket.emit). It is also the place to log connections and attach the "disconnect" handler.

6. What is the difference between socket.emit() and io.emit()?

socket.emit() sends an event only to the one client represented by that socket (for example a private welcome message). io.emit() broadcasts an event to every connected client. In this project, the welcome message uses socket.emit() and the menu notifications use io.emit(), so all users see them.

Related: socket.broadcast.emit() sends to everyone except the sender.

7. What are connection and disconnection events in Socket.IO?

connection (server) / connect (client) fires when the connection is established. disconnect fires when it ends – because the user closed the tab, lost network, called socket.disconnect(), or the server shut down; it gives a reason such as "transport close" or "ping timeout". Handling them lets us log online users, update UI status (the green/grey dot on the bell) and clean up resources.

8. Why is useEffect() used when integrating Socket.IO with React?

Opening a socket and registering listeners are side effects and must not run on every render. useEffect with an empty dependency array runs once when the component mounts, so the connection is created once. Its cleanup function (the returned function) removes the listeners and disconnects when the component unmounts, which prevents duplicate listeners, memory leaks and duplicate notifications.

9. What is the purpose of socket.off() and socket.disconnect()?

socket.off(event, handler) removes a specific event listener so the handler is no longer called – used in the useEffect cleanup to avoid registering the same listener repeatedly. socket.disconnect() manually closes the connection to the server (the server then logs a "disconnect" event) – used when the component or application is closed or the user logs out.

10. Explain how real-time notifications improve an Event Management System.

In an event management system (and here, a restaurant menu system) users see changes the moment an administrator makes them. They do not need to refresh or keep polling, so they never act on stale information – a new event or dish appears immediately, a changed price or time is visible at once, and a cancelled or removed item disappears. This improves user experience and engagement, reduces unnecessary HTTP requests to the server, and lets administrators communicate urgent changes instantly. In BiteOrder, customers see new dishes, price changes and removed dishes live, and the menu refreshes itself.

4.2 HTTP server and Socket.IO configuration (server/server.js)

Socket.IO needs the raw HTTP server, so the Express app is wrapped with http.createServer(). The io instance is stored in the app with app.set("io", io) so controllers can use it. The server starts with httpServer.listen() instead of app.listen().

const http = require('http');
const express = require('express');
const { Server } = require('socket.io');
const connectDB = require('./config/db');
const app = express();

// Socket.IO needs the raw HTTP server (Express alone is not enough)
const httpServer = http.createServer(app);
const io = new Server(httpServer, {
  cors: { origin: '*', methods: ['GET', 'POST'] },
});

// Make io available inside controllers via req.app.get('io')
app.set('io', io);

// Handle client connections and disconnections
io.on('connection', (socket) => {
  console.log(`🔌 Client connected:    ${socket.id}  (online: ${io.engine.clientsCount})`);
  socket.emit('welcome', { message: 'Connected to BiteOrder live updates', id: socket.id });

  socket.on('disconnect', (reason) => {
    console.log(`❌ Client disconnected: ${socket.id}  (reason: ${reason}, online: ${io.engine.clientsCount})`);
  });
});
connectDB().then(() => {
  httpServer.listen(PORT, () => {   // was app.listen(PORT, ...)
    console.log('BiteOrder API Server running at: http://localhost:' + PORT);
  });
});

4.4 Accessing Socket.IO in controllers and emitting notifications (server/controllers/menuController.js)

The controller gets the same io instance with req.app.get("io") and broadcasts a notification to all clients with io.emit().

// Broadcast a real-time notification to every connected client (Experiment 7)
const notifyClients = (req, type, item, message) => {
  const io = req.app.get('io');
  if (!io) return;
  io.emit('notification', {
    id: `${Date.now()}-${Math.random().toString(36).slice(2, 7)}`,
    type, // 'created' | 'updated' | 'deleted'
    message,
    item: { id: String(item._id), name: item.name, category: item.category, price: item.price },
    by: req.user ? req.user.name : 'Admin',
    timestamp: new Date().toISOString(),
  });
};

4.6 Listening for notifications and storing them in React state (client/src/context/NotificationContext.jsx)

useEffect connects once, registers listeners, stores each notification in state (newest first), shows a toast, and bumps menuVersion so the menu page re-fetches. The cleanup function calls socket.off() and socket.disconnect().

import React, { createContext, useContext, useEffect, useState, useCallback } from 'react';
import { socket } from '../socket';

const NotificationContext = createContext(null);

export function NotificationProvider({ children }) {
  const [notifications, setNotifications] = useState([]); // newest first
  const [toasts, setToasts] = useState([]);
  const [connected, setConnected] = useState(false);
  const [menuVersion, setMenuVersion] = useState(0); // bumps on every menu change -> pages refetch

  useEffect(() => {
    const onConnect = () => setConnected(true);
    const onDisconnect = () => setConnected(false);
    const onNotification = (n) => {
      setNotifications((prev) => [{ ...n, read: false }, ...prev].slice(0, 30)); // store in state
      setToasts((prev) => [...prev, n]);
      setMenuVersion((v) => v + 1);
      setTimeout(() => setToasts((prev) => prev.filter((t) => t.id !== n.id)), 6000);
    };

    socket.on('connect', onConnect);
    socket.on('disconnect', onDisconnect);
    socket.on('notification', onNotification);
    socket.connect();

    // cleanup: remove listeners and close the connection when the provider unmounts
    return () => {
      socket.off('connect', onConnect);
      socket.off('disconnect', onDisconnect);
      socket.off('notification', onNotification);
      socket.disconnect();
    };
  }, []);

  const unreadCount = notifications.filter((n) => !n.read).length;
  const markAllRead = useCallback(() => setNotifications((p) => p.map((n) => ({ ...n, read: true }))), []);
  const clearAll = useCallback(() => setNotifications([]), []);

  return (
    <NotificationContext.Provider value={{ notifications, toasts, unreadCount, connected, menuVersion, markAllRead, clearAll }}>
      {children}
    </NotificationContext.Provider>
  );
}

export const useNotifications = () => useContext(NotificationContext);

4.7 NotificationBell component (client/src/components/NotificationBell.jsx)

Shows the unread count badge, a connection indicator dot and a dropdown list. ToastStack (same file) shows the pop-up for a few seconds.

import React, { useState } from 'react';
import { useNotifications } from '../context/NotificationContext';

const STYLE = {
  created: { icon: '🆕', color: 'text-emerald-700', bg: 'bg-emerald-50', label: 'New' },
  updated: { icon: '✏️', color: 'text-blue-700', bg: 'bg-blue-50', label: 'Updated' },
  deleted: { icon: '🗑️', color: 'text-red-700', bg: 'bg-red-50', label: 'Removed' },
};

const timeAgo = (iso) => {
  const s = Math.max(0, Math.round((Date.now() - new Date(iso).getTime()) / 1000));
  if (s < 5) return 'just now';
  if (s < 60) return `${s}s ago`;
  return `${Math.round(s / 60)} min ago`;
};

// Bell icon with unread badge + dropdown list of received notifications
export default function NotificationBell() {
  const { notifications, unreadCount, connected, markAllRead, clearAll } = useNotifications();
  const [open, setOpen] = useState(false);

  const toggle = () => {
    if (!open) markAllRead(); // opening the list marks everything as read (badge clears on next render)
    setOpen(!open);
  };

  return (
    <div className="relative">
      <button
        onClick={toggle}
        aria-label="Notifications"
        className="relative w-10 h-10 rounded-xl bg-slate-100 hover:bg-slate-200 border border-slate-300 flex items-center justify-center cursor-pointer"
      >
        <span className="text-lg">🔔</span>
        {unreadCount > 0 && (
          <span id="bell-count" className="absolute -top-1.5 -right-1.5 min-w-5 h-5 px-1 rounded-full bg-red-600 text-white text-[11px] font-black flex items-center justify-center border-2 border-white">
            {unreadCount}
          </span>
        )}
        <span className={`absolute bottom-0.5 right-0.5 w-2 h-2 rounded-full ${connected ? 'bg-emerald-500' : 'bg-slate-400'}`} title={connected ? 'Live' : 'Offline'} />
      </button>

      {open && (
        <div id="bell-dropdown" className="absolute right-0 mt-2 w-80 max-w-[90vw] bg-white border border-slate-200 rounded-2xl shadow-xl z-50 overflow-hidden">
          <div className="flex items-center justify-between px-4 py-3 border-b border-slate-100">
            <span className="font-bold text-slate-900 text-sm">Notifications</span>
            <button onClick={clearAll} className="text-xs font-semibold text-slate-500 hover:text-red-600 cursor-pointer">Clear all</button>
          </div>
          <ul className="max-h-80 overflow-y-auto">
            {notifications.length === 0 && <li className="px-4 py-8 text-center text-sm text-slate-500">No notifications yet</li>}
            {notifications.map((n) => {
              const s = STYLE[n.type] || STYLE.updated;
              return (
                <li key={n.id} className="px-4 py-3 border-b border-slate-100 last:border-0 flex gap-3">
                  <span className={`w-9 h-9 shrink-0 rounded-lg ${s.bg} flex items-center justify-center`}>{s.icon}</span>
                  <div className="min-w-0">
                    <p className="text-sm text-slate-800 leading-snug">{n.message}</p>
                    <p className="text-[11px] text-slate-500 mt-0.5"><span className={`font-bold ${s.color}`}>{s.label}</span> · by {n.by} · {timeAgo(n.timestamp)}</p>
                  </div>
                </li>
              );
            })}
          </ul>
        </div>
      )}
    </div>
  );
}
